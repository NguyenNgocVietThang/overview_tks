## Recommended execution order

1. **001 first, standalone.** It touches only JavaScript (Chart.js animation gating) and is
   independent of every other plan — no CSS token dependency, no shared lines with the others.
   It's also the highest-leverage fix (both feel and real performance), so land it first.
2. **002 next.** It introduces the `--ease-out` token in `:root` that plans 003 and 005 both
   reference via `var(--ease-out)`.
3. **003 and 004 can run in either order after 002** — they touch disjoint parts of the file
   (003: `.suggestions` CSS + `hideSearchSuggestions`/`renderSuggestions`; 004: a new rule after
   `body{...}`) and neither depends on the other.
4. **005 last**, after 002 — it also consumes `--ease-out`, and edits the same
   `.debt-detail-row` rule that nothing else in this batch touches, so its ordering relative to
   003/004 doesn't matter, only that 002 lands first.

## Dependencies

- **002 → 003**: plan 003's target CSS uses `var(--ease-out)`. If applying 003 before 002, its
  own Boundaries section allows adding just that one token standalone as a fallback.
- **002 → 005**: same dependency and same fallback, spelled out in plan 005's Boundaries.
- **001 has no dependencies** on 002–005, and 002–005 have no dependency on 001. If only doing
  one plan, 001 is the recommended starting point (see severity table above).
